# Research Env Doctor · 科研计算环境诊断

> 给做分子模拟与计算材料的研究者：**conda 激活失败、命令找不到、MPI 崩溃、集群作业提交不上** —— 帮你定位原因，并**讲清为什么会这样**。

不是又一个"环境检测脚本"。它解决的是那个具体的、真实的困境：

> 你按教程装好了 GROMACS，跑起来报了一堆错，**你看不懂错在哪**，
> 搜了半天试了各种方法，两天过去了。

---

## 为什么做这个

上海交通大学的一位学生在记录用 AI 跑通 MD 工作流时，列出的困难是这样的：

> 队列资源不足、节点切换、**conda 激活失败**、依赖缺失、**文件格式不兼容**、
> 分析任务失败后重提……

原本要摸索数周的问题。而该课题组的 PI 的反思是：

> **大量以"熟练度"和"经验积累"为核心的知识，正在快速贬值。**
> 优势不再来自"你会不会执行"，而来自"你知不知道该执行什么"。

**本项目就是把"知道该执行什么"这部分固化下来。**

## 与通用环境诊断工具的分工

| 工具 | 负责范围 |
|---|---|
| [`env-doctor`](https://pypi.org/project/env-doctor/) | **GPU 驱动 → CUDA → cuDNN → PyTorch** 版本链 |
| **本项目** | **模拟软件与集群的软环境** —— conda / PATH / 依赖 / MPI / 作业提交 |

**互补，不竞争。** GPU 栈的问题请用 `env-doctor`。

---

## 它做什么（三层）

| 层 | 作用 |
|---|---|
| **① 预防** | 跑模拟**之前**体检：解释器、conda、MPI、依赖、磁盘、权限 |
| **② 诊断修复** | 报错后定位根因 + 给可执行的修复命令 |
| **③ 原理讲解** | **说清为什么会报这个错** —— 让你下次能自己判断 |

第 ③ 层是重点。只给命令，你下次还是不会；**讲清原理，才是"资深专家技能包"的价值。**

## 内容构成

```
research-env-doctor/
├── SKILL.md                    # 主入口：体检清单 + 诊断流程
├── references/
│   ├── errors.md               # 报错 → 原因 → 修法（含原理讲解）
│   └── pitfalls.md             # 10 个真实踩过的坑
└── README.md
```

### `references/errors.md` 覆盖

- **conda**：`command not found`、激活失败、环境找不到、包缓存膨胀
- **解释器**：`python` 版本不对、`ModuleNotFoundError`（pip 与 python 不同环境）
- **共享库**：`libXXX.so not found`、`undefined symbol`
- **MPI**：版本不匹配崩溃、`not enough slots`
- **集群**：作业立刻失败、CRLF 换行符陷阱、OOM、超时
- **权限**：`Permission denied` 的四种原因
- **Windows**：批处理闪退、PowerShell 编码陷阱、磁盘清理

### `references/pitfalls.md` 收录的真实陷阱

1. PowerShell 变量名不区分大小写 → 写错目标
2. **YAML 的 `[]` 不能包块状列表 → 配置无效 → 服务起不来**
3. `.bat` 里写中文 → cmd 按 GBK 解码 → 窗口闪退
4. 整目录删除因单个文件被占用而整体失败
5. 跨盘搬移必须先"复制 → 校验 → 才删源"
6. 只看空间不看性能地选目标盘（外置盘会拖慢 + 拔盘失效）
7. 同一物理盘的两个分区之间搬东西不产生新空间
8. `Get-Content -Encoding UTF8` 会吃掉 BOM
9. **改完配置不验证就交付 → 破坏半径最大**
10. 注册表全盘递归搜索会超时

## 怎么用

### 在支持 Skills 的 AI 助手里

把 `SKILL.md` 与 `references/` 放到技能的扫描目录，然后：

- 「帮我体检一下计算环境」
- 「我把报错贴给你：…… 帮我看看」
- 「我要跑 GROMACS，环境够吗」

### 单独阅读

`references/errors.md` 和 `references/pitfalls.md` 本身就可以当排错手册用，
不依赖任何 AI 工具。

## 安全底线

- 任何**删除/覆盖**操作前先备份，并告知备份位置
- **不改系统级配置**（`/etc/`、注册表 HKLM）除非你明确授权
- **不擅自 `conda remove` / `pip uninstall`** —— 先说明影响，等你确认
- **不确定就说不确定**，不给"看起来对"的命令
